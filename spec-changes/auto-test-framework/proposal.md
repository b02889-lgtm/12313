# 提案：自动化测试框架（auto-test-framework）

## 动机

当前工作区存在以下测试相关问题：

### 现状分析

1. **测试文件分散**：现有测试文件（`test_demo.py`、`test_calculator_skill.py`、`test_skills.py`、`test_weather_api.py`、`test_weather_mcp.py`）分散在根目录，缺乏统一管理
2. **无统一测试框架**：各测试文件使用不同的测试方式，有的用 `unittest`，有的只是简单的脚本执行
3. **缺乏测试覆盖率**：无法衡量现有代码的测试覆盖程度
4. **无自动化执行**：测试需要手动逐个运行，没有一键执行所有测试的机制
5. **缺乏测试报告**：测试结果无法持久化和可视化展示

### 业务影响

- **代码质量风险**：没有完整测试保护的代码，修改后可能引入回归 bug
- **开发效率低**：每次修改都需要手动验证，耗时且易遗漏
- **团队协作困难**：新成员难以理解代码预期行为，无测试作为文档参考

## 目标

建立一套**完整、可扩展的自动化测试体系**，实现：

1. ✅ **统一测试框架**：采用 pytest 作为标准测试框架，统一所有测试写法
2. ✅ **测试分层结构**：支持单元测试、集成测试、端到端测试的分层
3. ✅ **自动化执行**：一键运行所有测试，支持并行执行提升效率
4. ✅ **覆盖率报告**：自动生成测试覆盖率报告，设定最低覆盖率门槛
5. ✅ **测试报告可视化**：生成 HTML 格式的测试报告，便于查看和分享
6. ✅ **CI 集成就绪**：提供配置支持后续集成到 CI/CD 流水线

## 验收标准

| 标准 | 指标 |
|------|------|
| 测试框架统一 | 所有测试文件使用 pytest 风格编写 |
| 测试覆盖率 | 核心模块（scripts/、data-analysis/）覆盖率 ≥ 70% |
| 一键执行 | 执行 `pytest` 即可运行所有测试 |
| 执行时间 | 全量测试执行时间 < 60 秒（并行） |
| 测试报告 | 自动生成 HTML 报告到 `test-reports/` |
| CI 配置 | 提供 GitHub Actions 配置文件模板 |
| 文档完整 | 测试指南文档说明如何编写和运行测试 |

## 范围

### 包含

- **测试框架搭建**
  - pytest 及相关插件配置（pytest-cov、pytest-html、pytest-xdist）
  - 测试目录结构规划（tests/unit、tests/integration、tests/e2e）
  - 测试配置文件（pytest.ini、conftest.py）

- **现有测试迁移**
  - 将现有 5 个测试文件迁移到新结构
  - 重构为 pytest 风格
  - 修复跨目录 import 问题

- **新增测试用例**
  - 为核心工具模块编写单元测试
  - 为 MCP 服务器编写集成测试
  - 为数据分析流程编写端到端测试

- **测试报告系统**
  - 覆盖率报告生成（HTML + XML）
  - 测试结果报告（HTML）
  - 历史报告存档机制

- **自动化配置**
  - 测试执行脚本（run_tests.py 或 Makefile）
  - GitHub Actions 配置模板
  - pre-commit 钩子配置

### 不包含

- 性能测试/压力测试（属于性能监控提案范畴）
- 安全测试/渗透测试
- UI 自动化测试（当前项目无 UI）
- 测试数据自动生成工具（可作为后续扩展）

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 测试框架 | pytest | Python 社区最流行的测试框架，语法简洁，插件丰富 |
| 覆盖率工具 | pytest-cov | 与 pytest 深度集成，支持多种报告格式 |
| HTML 报告 | pytest-html | 美观易读的 HTML 测试报告 |
| 并行执行 | pytest-xdist | 支持多进程并行执行，加速测试 |
| Mock 工具 | pytest-mock | 简化 mock 对象创建 |
| 固件管理 | pytest fixtures | 内置的测试数据管理机制 |

## 风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 现有测试迁移失败 | 中 | 低 | 保留原测试文件备份，逐步迁移验证 |

| 测试执行时间过长 | 低 | 低 | 合理使用 mark 分组，支持部分测试执行 |
