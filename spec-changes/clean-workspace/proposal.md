# 提案：整理工作区文件结构（clean-workspace）

## 动机

当前工作区根目录下堆积了 **60+ 个松散文件**，包含多种类型混杂在一起：

- Python 脚本（20+个）：从简单 demo 到数据分析工具
- Markdown 文档（15+个）：项目说明、修复报告、诗词创作
- 配置/JSON 文件（5+个）：MCP 配置、通用配置
- 批处理/脚本文件（5+个）：Figma 启动、PowerShell 工具
- 中文文本文件（4个）：杂项笔记
- 数据文件（3个）：CSV、JSON 样本数据
- 其他：DOCX、图片文件夹、临时测试文件

**问题：**
1. 文件无分类，找东西困难
2. 实验性代码和正式工具混在一起
3. 临时/测试文件占据空间和注意力
4. MCP 服务器已有子目录，但其他文件没有组织

## 目标

将根目录从"文件堆"整理为**清晰的目录结构**，使得：

1. ✅ 每类文件都有明确归属
2. ✅ 根目录只保留必要的顶层文件（README、.gitignore 等）
3. ✅ 临时/实验文件被识别并归类或清理
4. ✅ MCP 服务器目录保持不变（已有良好结构）
5. ✅ 配置文件（.copilotcode/、.claude/）保持不变

## 验收标准

| 标准 | 指标 |
|------|------|
| 根目录文件数 | ≤ 5 个（README.md、.gitignore、.copilotcodemodes、config.json + spec-changes 目录） |
| 所有 Python 文件 | 归入对应子目录，import 关系不断裂 |
| 所有 Markdown 文档 | 归入 `docs/` 或其子目录 |
| 临时文件 | 全部归入 `archive/`，经用户确认后可删除 |
| 已有 MCP 服务器 | 零修改，功能不受影响 |
| Git 历史 | 保留完整，可通过 git log --follow 追踪文件移动 |

## 范围

### 包含
- 根目录下所有松散文件的分类和归档
- 创建合理的目录结构
- 识别可安全删除的临时文件

### 不包含
- 修改已有子目录内部结构（如 `custom-tools-mcp/`、`weather-mcp-server/` 等）
- 修改 `.copilotcode/` 或 `.claude/` 配置
- 修改文件内容（只移动文件位置）

## 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 移动文件后引用路径失效 | 中 | 先检查文件间的 import 关系；采用 sys.path.insert() 修复（见 design.md） |
| 误删有用文件 | 高 | 先列出待删除清单，经用户确认后执行；archive/ 设置退出策略 |
| Git 历史影响 | 低 | Git 能追踪文件移动 |
| 整理后重新混乱 | 中 | 建立维护机制：README 指南、.gitignore 增强、定期检查（见 design.md） |
| Import 修复方案选择不当 | 低 | 采用渐进策略：短期 sys.path.insert()，长期可升级为 pyproject.toml |
| archive/ 永久堆积 | 低 | 设置明确的保留期限和清理触发条件，维护 CLEANUP_LOG.md |
