# 提案：AI 驱动的代码健康守护者 (AI Code Guardian)

## 1. 动机 (Motivation)

在目前的工作区中，我们有独立脚本、多个 MCP 服务器以及正在规划的多个独立工具（自动化测试、API文档生成、性能监控、多语言管理）。然而，这些工具如果彼此孤立，将带来极大的维护负担：
- 开发者在写完代码后，需要**手动**去写测试。
- 开发者修改了接口，需要**记得**去更新文档。
- 只有在线上运行变慢时，才会**事后**去挂载性能监控。
- 写到一半发现有中文硬编码，需要**中断心流**去处理国际化。

我们需要从“事后补救”和“纯手动操作”转向“**开发时拦截**”和“**AI 自动化补全**”。

## 2. 目标 (Goals)

构建一套挂载在 Git Hooks (pre-commit) 或 CI 流程上的**智能自动化流水线**，它将各个独立提案的功能通过 LLM 缝合在一起：

1. **AI 辅助测试生成与变异防御**：通过 AST 分析代码变更，当发现新增无测试的函数时，自动调用 LLM 生成 `pytest` 用例；引入变异测试（Mutation Testing）确保测试有效性。
2. **API 破坏性变更检测 (Breaking Change Detector)**：每次提交时对比新旧 AST。如果删除了参数或改变了返回值类型，自动阻断并提示，防止隐式破坏。
3. **性能退化拦截与智能建议**：在执行自动化测试的后台开启性能探针。如果发现新代码的时间复杂度退化，不仅报告性能变慢，更利用 LLM 提供优化代码片段（如 O(n²) 转 O(1)）。
4. **硬编码审查与无感多语言化**：拦截代码中的中文/魔法字符串，自动弹窗建议，并在后台由 LLM 根据上下文完成精准翻译，自动替换为 `i18n.t(...)`。

## 3. 核心理念 (Core Philosophy)

- **零配置、零打扰**：它不应该是一个需要开发者经常配置的系统。开发者只管写业务代码，它在后台默默工作，只有在发现问题（性能下降、API 破坏）或可以提供帮助（生成测试）时才介入。
- **预防胜于治疗**：将所有质量控制点前置到本地开发或 Commit 阶段。

## 4. 非目标 (Non-Goals)

- 不开发全新的 IDE 插件（依赖现有的命令行交互或 pre-commit 提示）。
- 不替代高级的 APM（如 Datadog），仅限于本地/CI 级别的静态分析和微基准测试。

## 5. 范围 (Scope)

该守护者将作为一个基于 Python 的 CLI 工具 (`guardian-cli`) 实现，能够作为 git pre-commit hook 运行。它将整合 `pytest`、`mkdocstrings`、AST 分析库以及 Claude/OpenAI 的 API 接口。
