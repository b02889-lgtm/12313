# 提案：多语言国际化管理器 (i18n-manager)

## 1. 动机 (Motivation)
当前项目在处理多语言国际化 (i18n) 时存在手动工作量大、易漏翻、同步困难等问题。特别是对于动态插值文本的维护，以及脱离代码上下文导致的"不知所云"的翻译问题，极大地降低了本地化质量。为提升多语言开发效率和翻译质量，我们需要一个自动化的、具备上下文感知的多语言国际化管理器。

## 2. 目标 (Goals)
- 自动扫描并提取代码中的硬编码文本，**包含动态插值与变量模板**。
- 采用**基于文件路径的命名空间**生成语义化的 Key，保留词条的代码来源。
- 提供与大模型（LLM）的深度集成，**利用代码上下文（AST 提取的相邻代码）进行"语境翻译"**，大幅提高机器翻译准确率。
- 生成标准化的语言资源文件（如 JSON/YAML 格式），支持嵌套与展平双重模式。
- 提供增量更新能力，仅对新增或修改的文本进行提取和翻译，不影响已确认的翻译。
- 支持检查缺失的翻译键值，提供完整的翻译覆盖率报告。

## 3. 非目标 (Non-Goals)
- 不负责运行时多语言切换的框架级实现（如不替代 `i18next` 或 `vue-i18n`，仅做构建/开发期的辅助管理）。
- 不提供复杂的带用户界面的翻译管理系统 (TMS)，核心通过 CLI 或脚本交互。

## 4. 范围 (Scope)
该工具将作为一个独立脚本或 CLI 工具运行，支持前端和后端常见的源码文件扩展名（如 `.js`, `.ts`, `.vue`, `.py`, `.html` 等）。主要服务于开发阶段的代码文本提取和具备上下文感知的智能语言文件同步。
